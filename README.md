# Decision Models for Bengali Virtual Assistant Intent Detection

Code, data and model outputs for the paper **"Decision Models for Bengali Virtual Assistant Intent Detection: An Analysis of Cross-Script Transfer."**

We fine-tune Qwen3.5-0.8B as a decision model in the style of Cloudflare's Clef. The model reads a user request together with a list of candidate intents and returns a probability for each intent in one forward pass, without generating text. We test it on four written forms of the same requests (English, Bengali in Bangla script, Romanized Bengali and code-mixed Bengali-English), compare three fine-tuning strategies (direct, sequential and joint) and compare the result with baselines.

## Main results

Accuracy on 2,000 test utterances per form. CM is the code-mixed test set, which covers 13 of the 60 intents.

| Strategy | Model | En | Bn | Rom | CM |
|---|---|---|---|---|---|
| Direct | English model | .827 | .686 | .333 | .771 |
| Direct | Bengali model | .799 | .773 | .314 | .790 |
| Direct | Romanized model | .717 | .651 | .598 | .695 |
| Direct | CM model | .669 | .536 | .301 | .962 |
| Sequential | En→Bn model | .836 | .775 | .318 | .809 |
| Sequential | En→Bn→CM model | .791 | .696 | .310 | **.978** |
| Sequential | En→Bn→CM→Rom model | .826 | .758 | .640 | .954 |
| Joint | Joint model (all four) | **.853** | **.793** | **.669** | .966 |
| Baselines | Qwen3.5-0.8B (base model, untrained head) | .066 | .064 | .034 | .100 |
| Baselines | TF-IDF model (all four) | .760 | .744 | .728 | .972 |
| Baselines | XLM-R (full fine-tuning, all four) | .697 | .634 | .281 | .648 |

- Joint training beats the final sequential model on every form, and all differences are significant under exact McNemar tests with Holm correction.
- English and Bangla script transfer well to each other. Romanized Bengali gets almost nothing from either and needs its own training data.
- The decision model beats the character n-gram TF-IDF baseline on English (+9.3 points) and Bengali (+4.9), loses on Romanized (-5.9) and ties on code-mixed text.
- Every fine-tuned model trained without Romanized data scores 30-33% on Romanized text. Token counts rule out over-segmentation (Bangla script is split more finely, 2.61 vs. 1.86 tokens per word, yet transfers well).
- The 13-intent code-mixed stage biases the sequential model's head toward those intents (62% of Bengali predictions vs. a true share of 44%). Joint training shows no such bias.
- The joint model gives the same intent to the English, Bangla-script and Romanized versions of an utterance only 64.9% of the time.
- Answering only the 80% most confident inputs raises joint-model accuracy to 93.6% (En), 88.7% (Bn) and 78.2% (Rom).
- The joint decision model also beats a fully fine-tuned XLM-R on every form (+15.6 points on English, +15.9 on Bengali, +38.8 on Romanized, +31.8 on code-mixed).

The XLM-R baseline was trained and evaluated by a collaborating researcher on the same joint training data and test sets. Its prediction files are not included in this repository.

## Data

The English and Bengali sets are a 5,000-ID subset of [MASSIVE 1.1](https://github.com/alexa/massive) (60 intents). Each ID carries the same request in `en-US` and `bn-BD`. We use 3,000 IDs for training and 2,000 disjoint IDs for testing, drawn from all three MASSIVE partitions, so the results are not comparable with MASSIVE's official test split.

The Romanized and code-mixed sets were generated by Claude Sonnet 5.5 from the MASSIVE utterances and labels. Two human annotators each checked every utterance and corrected any errors they found. The Romanized set transliterates the Bengali files and keeps their IDs. The code-mixed set was generated separately, is not parallel to the others and covers only 13 of the 60 intents. It also has more train-test lexical overlap: 136 test utterances have a training counterpart with word-overlap ratio of at least 0.8, against 86 for Bengali.

| File | Form | Split | Rows | Label column |
|---|---|---|---|---|
| `en_3000match.csv` | English | train | 3,000 | numeric ID |
| `bn_3000_clean_unique.csv` | Bengali | train | 3,000 | numeric ID |
| `banglish_massive_train.csv` | Romanized | train | 3,000 | intent name |
| `train_set_codemixed_massive60_fixed.csv` | Code-mixed | train | 3,000 | intent name |
| `test_en_2000.csv` | English | test | 2,000 | intent name |
| `test_bn_2000.csv` | Bengali | test | 2,000 | intent name |
| `banglish_massive_test.csv` | Romanized | test | 2,000 | intent name |
| `test_set_codemixed_massive60_fixed.csv` | Code-mixed | test | 2,000 | intent name |
| `massive_intent_mapping.csv` | | | 60 | maps numeric IDs to intent names |

"Banglish" in file names means Romanized Bengali. The two training files with numeric labels are mapped to intent names with `massive_intent_mapping.csv`, which both the notebook and the scripts do automatically.

Each fine-tuned repository holds a LoRA adapter and the decision head on top of Qwen3.5-0.8B. To evaluate one, set `LOAD_SAVED_MODEL = True`, `WILL_FT = False` and `saved_model_path` to its repository name in the notebook.

## Training and evaluation

`decision_model_finetune.ipynb` was run on Kaggle T4 GPUs. It loads Qwen3.5-0.8B through Unsloth's `FastDecisionModel`, adds a LoRA adapter, trains with `DecisionTrainer` and evaluates on all four test sets.

**Setup**

1. Upload the files in `Dataset/` as a Kaggle dataset and change the paths in the configuration cell to point to it.
2. Add a Hugging Face token under *Add-ons > Secrets* with the name `HF_TOKEN` (needed only to push or load private models).
3. Run the installation cell, then the rest of the notebook.

**Configuration flags**

| Flag | Meaning |
|---|---|
| `WILL_FT` | `True` trains a model. `False` only evaluates. |
| `LOAD_SAVED_MODEL` | `True` loads `saved_model_path` (for evaluation, or as the starting point of the next sequential stage). |
| `base_model_inference` | Evaluates the currently loaded model before training. |
| `remote_repo` | Hugging Face repository the trained model is pushed to. |

The training data is chosen through the `frames` list in the data-loading cell. A direct model uses one form, a joint model uses all four, and each sequential stage loads the previous stage's model and trains on the next form.

**Hyperparameters** (identical for every model)

| Setting | Value |
|---|---|
| Backbone | Qwen3.5-0.8B, fp16, no quantization |
| LoRA | r = 16, alpha = 16, dropout = 0 |
| Optimizer | learning rate 2e-4, cosine schedule, 10 warmup steps, weight decay 0.01 |
| Batch | 8 per device, gradient accumulation 4 |
| Epochs | 2 |
| Max sequence length | 2,048 tokens |
| Seed | 3407 |
| Prompt | "What is the user's main intent?" with a one-line description of each candidate intent |
| Decision head | Clef-style, 4 layers, width 512, 8 attention heads, 2 routing layers, over Qwen's 1,024-dim hidden states |
| Steps | 188 per 3,000-utterance run |
| Parameters | 891M total, 38.1M trained (LoRA adapters + head) |

During training, each example gets a sampled candidate set: all 60 intents (probability 0.35), 20-40 intents (0.40) or 6-20 intents (0.25). Each set holds the gold intent and one to three hard negatives from the same domain (e.g. `alarm_query` for `alarm_set`), with the rest filled at random and shuffled. At test time all 60 intents are offered.

## Model run outputs

Each folder in `Model Run Outputs/` holds the evaluation of one model on the four test sets: per-utterance predictions with confidences (`*_predictions.csv`), per-class scores, confusion matrices, a text report and a summary (`summary_all_datasets.csv`) with accuracy, Wilson interval, macro-F1, ECE and other metrics.

| Folder | Model |
|---|---|
| `output_base` | Base model with untrained head |
| `Outputs EN_FT` | Direct English |
| `Outputs BN FT` | Direct Bengali |
| `Outputs_Banglish_FT` | Direct Romanized |
| `outputs CM_FT` | Direct code-mixed |
| `Outputs plus_Bengali` | Sequential stage 1: English, then Bengali |
| `Outputs plus_CM` | Sequential stage 2: + code-mixed |
| `Outputs plus_romanized` | Sequential stage 3 (final): + Romanized |
| `Outputs Joined FT` | Joint, all four forms |

File prefixes: `EN` English, `BN` Bengali, `Banglish` Romanized, `CM` code-mixed. The `Outputs EN_FT` run uses the older prefix `Romantized` for Romanized.

## Analysis scripts

The scripts in `analysis/` run on a CPU and need no GPU. Run them from the repository root:

```bash
pip install pandas numpy scikit-learn matplotlib
python analysis/tfidf_baseline.py .
python analysis/mcnemar_tests.py
python analysis/a1_mcnemar_vs_tfidf.py
python analysis/cross_form_consistency.py
python analysis/selective_prediction.py
python analysis/label_bias.py
python analysis/token_analysis.py
python analysis/a4_error_analysis.py
python analysis/paper_figures.py
```

| Script | Output |
|---|---|
| `tfidf_baseline.py` | TF-IDF (character 1-5-grams) + logistic regression baseline, `tfidf_baseline.csv`, `tfidf_predictions/` |
| `mcnemar_tests.py` | Joint vs. sequential and direct Bengali vs. direct English tests, `mcnemar_results.csv` |
| `a1_mcnemar_vs_tfidf.py` | Decision model vs. TF-IDF tests, `a1_mcnemar_vs_tfidf.csv` |
| `cross_form_consistency.py` | Same prediction across the parallel English, Bengali and Romanized test IDs |
| `selective_prediction.py` | Accuracy when only confident predictions are kept |
| `label_bias.py` | Effect of the 13-intent code-mixed stage on predicted labels, `label_bias.png` |
| `token_analysis.py` | Qwen3.5 tokens per utterance and per word, `token_stats.csv` (needs `huggingface_hub` and `tokenizers`) |
| `a4_error_analysis.py` | Per-domain accuracy and error analysis |
| `paper_figures.py` | Transfer heatmaps, reliability and risk-coverage figures in `figures/` |
